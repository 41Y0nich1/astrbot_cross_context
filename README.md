# 跨窗口交接（astrbot_plugin_cross_context）

> 换窗口时，把上一个窗口最后一段对话递过去——只作参考，不改人格，不写记忆。
>
> 作者：Botanya泊宁

在 AstrBot 里换一个说话窗口时，自动把另一个窗口最近一段对话贴到当前请求前面，让接话的人知道刚才聊到哪儿了。

只作参考，不改人格、不改历史、不改上下文。

## 它解决什么

同一个人在网页和 QQ 之间来回切，AstrBot 是两个互不相通的会话。切过去的第一句话，对面拿不到任何前情，只能从零开始问「你刚说什么」。

这个插件在检测到「换窗口」时，把上一个窗口的最近几轮对话整理成一小块，直接拼在本次 prompt 的前面。块只活在这一轮请求里，不会写进历史记录。

## 怎么工作

1. 每次请求把当前这条用户消息记进该窗口的**时间线**（`events`：role + text + ts），并在回复定型后把这一轮的真实输出也记进去。
2. 请求到来时，如果本次窗口和上一次不同，就从上一个窗口的时间线里取最近的一段，拼成交接块，前置到 `req.prompt`。
3. 交接块自带 `〔交接开始〕` / `〔交接结束〕` 标记，写入前会把标记整段剥掉，避免自我嵌套。

### 怎么取舍字数

交接块总长不超过 `max_chars`（默认 2000），拼装规则：

- 从**最新的一条**往回装，末尾天然对齐上一个窗口的最后一条消息；
- 单条装得下就整条放，不切半句；
- 遇到装不下的那条，如果预算还剩 80 字以上，就剪下它的尾巴保留，并从最近的句读处起头；否则整条丢弃；
- 结果按时间正序输出，`·` 开头是对方说的，`我：` 开头是自己说的。

也就是说：越新越重要，旧消息只在上限不够时才被牺牲。

## 安装

插件市场搜索「跨窗口交接」安装，或手动把整个目录放到 `AstrBot/data/plugins/` 下，然后重载插件。

要求 AstrBot >= 4.10.4。

## 配置

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | 总开关。关闭后插件完全不介入 |
| `max_turns` | int | `4` | 每个窗口最多保留多少轮事件（下限按 40 条计），范围 1~12 |
| `max_chars` | int | `2000` | 交接块字数上限，范围 200~4000 |

一般不用动。真要调，`max_chars` 是唯一影响观感的那个：太小会只剩一两句，太大会挤占本轮 prompt 的注意力。

## 边界

- **只在换窗口时注入。** 同一个窗口内不重复贴，历史本来就在上下文里。
- **状态存在 `data/plugin_data/astrbot_plugin_cross_context/state.json`。** 只保留最近 6 个窗口，更旧的自动淘汰。
- **一条回复如果被拆成多条消息发送，只保留最后一段。** 这正是「最后一段输出」的语义，不是丢数据。
- **任何异常只写日志，不打断对话。** 交接失败最多是这一轮没有前情，不会让消息发不出去。
- **不写长期记忆。** 它只负责让这一轮接上话，不负责保存。

## 排错

切过去发现没有交接块，按顺序看：

1. 日志里有没有 `[cross_context] 注入交接块 ... 字`——没有说明没触发（可能还是同一个窗口，或者 `enabled` 关了）；
2. 有日志但块是空的，看 `state.json` 里上一个窗口的 `events` 是否为空；
3. 日志里出现 `回写回复失败`，说明取回复的接口对不上当前 AstrBot 版本。
